# Logic Sim - PROJECT NOTES (changelog, newest first)

**Logic Sim** is an offline simulator and viewer of a plant's DCS logic drawings: the DITL digital pages and 54 analog (ABC) control sheets. It reads the drawings (DXF), builds the logic and runs it: inputs, forces, switches, timers, PID loops, valves, with live colours on the wires. It runs as one html file in Chrome, as a portable Windows app and as an Android app.

Rules are NOT here any more: see DESIGN.md. Older entries (v1.8.1 and before): archive/notes/CHANGELOG-to-v1.8.1.md

## v1.13.1 (logic-sim-v1.13.1.html) - wire colours in Trace / Step no longer hide the signal state
- USER: the wire colours became confusing in Run / Pause / View / Trace. ASSESSMENT (screenshots of each mode): Run, Pause and View look the same by design (colour = state: live colour = 1, grey = 0, analog colour, forced dashed). - FIX: Trace and Step now draw a GLOW around the wire; the wire keeps its own state colour. Glow: white = selected (and the wires that changed after a Step, for 2 s), blue = driven by (upstream), magenta = feeds (downstream); the other wires are only dimmed to 35 %.

## v1.11.0 (ditl-workbench-v1.11.0.html) - REAL PID (user: "can the gains wait? fix the PID now")
- Gains are NOT needed to get the controller structure right: they only decide how FAST the output moves, not WHAT it does (modes, direction, limits, tracking, which signals drive it). So the PID is built now with DEFAULT tuning (Kp 1, Ti 60 s, Td 0) that is EDITABLE per block in the block panel (saved in the project file); the real values live in the DCS database and can be typed in / imported later.
- Algorithm: input = the DEVIATION from the DEV block (SV - PV) as drawn; es = ±deviation / span x 100 (span = range of the transmitter that feeds the deviation, found by tracing upstream, else 100); u = Kp*(es + integral(es)/Ti + Td*des/dt), clamped to the output range (default 0..100), integral frozen / back-calculated at the limits (anti-windup); at dt = 0 (Pause) only the proportional part moves; when the T/AMT after the controller is on another input the controller TRACKS that output (bumpless), the existing tracking hook of the selector is used.
- BUG FOUND AND FIXED: the ACT:R / ACT:N text is above the box, the old reader looked at its corner, so ALL 68 controllers were read as one action. Now 38 are reverse (ACT:R: flow / level feed) and 30 normal = direct (ACT:N: steam pressure blow-off), consistent with the process and with the DCS Module Wiring "Act (N:Nr, R:Rv)".
- TEST tools/test-pid.js (ABC-017, first-order plant): reverse action + positive plant reaches SV (30) and follows an SV step; Pause does not move the integrator; anti-windup recovers (MV 100 -> 47 after the error reverses); manual value 37 -> PID tracks 37, back to auto 37.00 -> 37.02 (bumpless); direct + negative plant converges; ACT parsed 38 / 30. Project file, circles, anim, numeric-input tests pass; triage stuck outputs 198 -> 190.
- NOT done (waits for data / decisions): real Kp / Ti / Td / alarm limits (DCS database), REM/LOC and local/remote SV, EX-MV / EX-CMD, PID type variants (PI-D, I-PD), PIDV differences.
- The user also sent claude_import.zip (LINEAR, Compensation, Drum Level, IO list, Memory 101-105 as .xls): read in a scratch folder only, not committed (see docs/BACKLOG.md).

## v1.10.2 (ditl-workbench-v1.10.2.html) - manual numeric input lost in Run mode (bug report from the user's laptop)
- SYMPTOM: type 77 in the numeric box, press the check button -> "Type a number first, then press ✓" (FORCE) or nothing applied (INPUT), only while RUN is on; Enter worked; Pause worked; other devices worked.
- CAUSE (diagnosis suggested by the user via another assistant, VERIFIED in the code and reproduced): the panel updater runs every 100 ms in Run and restored each box when `document.activeElement !== box`. Pressing the check button moves focus to the button, so the next tick overwrote the typed number (FORCE box -> '', INPUT box -> old value) before the click was processed. My earlier tests used Enter / instant programmatic clicks, so they never hit it. Timing + browser focus rules explain "some devices work".
- FIX (smallest): per-field dirty state `anEdit()`: dirty from the first typed character until committed (check / Enter / change), cancelled (Esc, release) or abandoned (2.5 s after losing focus); the updater skips dirty fields. Applied to FORCE box, INPUT box (inCtl) and the panel number boxes (analog inputs, setpoints, transmitters). Slider code untouched.
- TEST (tools/test-numinput.js, REAL mouse down 350 ms then up on the check button): v1.10.1 = FAIL for FORCE and INPUT in Run; v1.10.2 = OK in Run and Pause for click and Enter, FORCE and INPUT. Clock keeps running after the commit, slider still works, no page errors. Project file / circles / storage tests unchanged.
